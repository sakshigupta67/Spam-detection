# Spam Email Detection with Multinomial Naive Bayes

## Project Overview
This project builds a spam email detection system using a Multinomial Naive Bayes classifier implemented manually in Python. It uses the word-count email dataset and fits the classifier without using machine-learning libraries for the Naive Bayes calculations.

## Objective
The primary objective is to classify emails as spam or not spam using word frequencies. The assignment requires a clear, manual implementation of Naive Bayes probability calculations including class priors, feature likelihoods, Laplace smoothing, log probabilities, and evaluation metrics.

## Dataset Description
The dataset is a CSV file containing email word-count features and a binary target label. Each row represents one email. The first column is the email identifier/name, the last column is the label, and the remaining columns are word count features.

## Dataset Dimensions
The actual dataset used in this project contains 5172 rows and 3002 columns.

- 5172 emails
- 3002 columns total
- 1 identifier column
- 3000 word-count features
- 1 target label column

## Meaning of the Columns
- First column: email identifier/name (not used as a model feature)
- Middle 3000 columns: frequency counts of words in the email
- Last column: target label where 1 = spam and 0 = not spam

## Train/Test Split
The dataset is split before any parameter estimation to avoid data leakage.

- Training samples: 4500
- Testing samples: 672
- Random split: fixed NumPy permutation with a seed of 42

This follows the required assignment split exactly.

## Why Multinomial Naive Bayes is Appropriate
The input data contains non-negative integer word counts, which is a natural fit for Multinomial Naive Bayes. Each email is represented as a vector of counts, and the model assumes each feature contributes independently given the class.

## Naive Bayes Formula
The classifier estimates a class score for each email using:

log P(c) + sum(feature_count_j * log P(word_j | c))

where:
- P(c) is the class prior probability
- P(word_j | c) is the likelihood of feature j given class c

## Class Prior Calculation
For each class c:

P(c) = count(class c) / total number of training emails

## Word Likelihood Calculation
For each class c and feature j:

P(word_j | c) = (count(word_j, c) + alpha) / (total word counts in class c + alpha * vocabulary_size)

## Laplace Smoothing
Laplace smoothing is applied to avoid zero probabilities when a word never appears in a class. In this implementation, alpha = 1.0 by default.

## Why Log Probabilities Are Used
The direct product of many probabilities is extremely small and can underflow numerically. Using log probabilities allows the model to work stably while preserving the same ordering between classes.

## How the Classifier Works
1. Load and validate the dataset.
2. Remove the identifier column and keep the numeric word-count features.
3. Split the dataset into training and testing subsets.
4. Compute class priors and smoothed word likelihoods for the training data.
5. Use log scores to predict the class of each test email.
6. Evaluate the classifier with confusion matrix and metrics.

## Evaluation Metrics
